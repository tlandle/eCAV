## Plan Summaries

### litserve_performance_plan.md — ✅ Mostly complete
Goal: Quantify and reduce latency between local and LitServe-distributed YOLO inference.

Key result: Native 640×480 CARLA camera (matching YOLO inference resolution) cut e2e from ~82ms → ~22ms (−73%). The resolution match eliminated encode/decode overhead that dominated the baseline.

Optimization status:
- O1: `requests.Session` keep-alive ✅
- O2: JPEG compression ✅
- O3: msgpack response ✅
- O4b: TurboJPEG codec ❌ reverted (gains came from resolution, not codec)
- O4c: NVJPEG ⏸ deferred (encode/decode now negligible)
- O5: gRPC transport — completed as part of grpc_perception_migration

### grpc_perception_migration.md — ✅ Complete
Goal: Migrate YOLO distributed perception from HTTP/msgpack to gRPC.

Implemented: `perception.proto` defines `YoloRequest`/`YoloResponse`/`PerceptionService`; `perception_servicer.py` implements the gRPC server; `ml_manager.py` uses persistent gRPC channel. Message size limit: 16 MB.

### worldfusion_litserve_plan.md — 🔄 In progress
Goal: Enable and optimize WorldFusion on LitServe HTTP endpoint (port 18000, `/extract_features`).

Phase 0 (enable) ✅, Phase 1 (instrument) ✅, Optimizations O1+O4 ✅, O5 pending.

See [current_state.md](current_state.md) for measured performance data.

### edge_architecture_proposal.md — ⏳ Not started
Goal: Standalone edge process that owns per-edge actor coordination, tick barrier, and LitServe batching.

8-phase plan:
- Phase 0: CLI flag cleanup (`--litserve`, remove `distributed` from YAML)
- Phase 1: Proto updates (edge registration RPCs in `ecloud.proto`)
- Phase 2: YAML schema updates (edge_index, edge_port fields)
- Phase 3: C++ orchestrator (edge registration routing, edge tick logic)
- Phase 4: Standalone `edge_process.py`
- Phase 5: Actor client updates (edge discovery at runtime)
- Phase 6: Scenario config parsing
- Phase 7: `start_actors.sh` updates
- Phase 8: Build, test, validate

Key design decision: actors discover their edge at registration time; edge manages its own tick barrier (not the C++ comms server directly).
