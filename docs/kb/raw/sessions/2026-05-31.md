## Problem

Late fusion scenario (`openscenario_3_edge_late_fusion`) failing in both sequential and edge-only mode:
- Vehicles colliding
- No trajectory predictions visible on screen
- Ego braking constantly for phantom obstacles (73 brake events, 0 true positives)

## Root Cause: AB3DMOT Output Row Index Shift

`Box3D.__init__` in `AB3DMOT_libs/box.py` defaults `self.s = 0.0` (not `None`). The `bbox2array_raw()` method checks `if bbox.s is None:` — since `s=0.0` is never `None`, it always returned 8 elements `[h,w,l,x,y,z,ry,s]` for KF-state bboxes (the KF state has no confidence score).

This shifted every field after the bbox in the output row by +1:

```
Expected layout: d[7 elems] | track_id | carla_id | guid | vel[0,1,2] | info[3 elems]
Actual layout:   d[8 elems] | track_id | carla_id | guid | vel[0,1,2] | info[3 elems]
                    ^score
```

Reading with the expected (wrong) indices:
- `trk[7]` → s-score = 0.0 (read as track_id)
- `trk[8]` → track_id = 0 (read as carla_id → ALL tracks showed carla_id=0)
- `trk[10]` → trk.guid (GUID counter, starts at 1) (read as KF dx velocity)
  → `kf_speed = guid / dt = 1 / 0.05 = 20 m/s` phantom speed on every track from tick 0

Downstream effects:
1. **[OWN-BEACON] suppression never fired**: beacon track had `carla_id=0`, not the vehicle's real CARLA ID (e.g., 436), so `0 ∉ managed_ids_supp={436}` → not suppressed
2. **Speed gate never suppressed beacon**: `obs_spd=20 m/s`, ego starts at 0 m/s → `|20-0|=20 ≥ gate=3.0` → not suppressed
3. Ego's trajectory planning saw its own ghost predicted to be in its path → `[TRAJ_COLL] ttc=0.00` every tick → emergency braking → ego never moved

Secondary issue (also fixed): `predictor_type: smart` in YAML. SMART predictor requires `_MIN_HIST_IDENT = _MIN_HIST_ANON = 22` ticks of track history. Lincoln only visible ~9 ticks before the intersection. Even with the index bug fixed, SMART would never generate a prediction. Changed to `predictor_type: linear`.

## Fix

`AB3DMOT_libs/model.py`, `output()` method, line 530:

```python
# Before
d = Box3D.bbox2array_raw(d)
# After  
d = Box3D.bbox2array_raw(d)[:7]  # strip score — KF state has no confidence
```

Strips the phantom `s=0.0` score from the output row, restoring the 16-element layout that all downstream consumers assume.

## Why This Wasn't Caught Earlier

The bug predates the edge-only work. Sequential late fusion appeared to work in earlier testing (commit `96ab86c0`, 2026-05-03) because the evaluation framework wasn't checking `ghost_brake_events` — the phantom braking went undetected since the scenario was declared "done" at `Reached maximum step limit` without examining vehicle behavior.

The edge-only debugging session made the ghost track visible (via `[TRACKS]` logging) and the `[SUPP-TRACE]` instrumentation made `cid=0` and `kf_speed=20.0` unmistakably wrong.
