## What Was Done

### Proto changes (`ecloud.proto`)
- Added `bytes pickled_predictions = 5` to `FusionResult` — carries per-vehicle `ObstaclePrediction` objects so `ecav.py` can inject them after `Edge_PerformFusion` returns. The existing `detections` field carries `EdgeObstacleObject` proto structs, which the planning pipeline can't use directly.
- Added `rpc Edge_EndScenario(Empty) returns (EdgeEvaluationResult)` — ecav.py calls this at scenario end; edge finalizes profiler and returns it.
- Stubs recompiled with `python ecav.py --build` and copied to `ecav/protos/`.

### `ecav.py` fix
- `--build` flag was unreachable: it was checked after scenario YAML validation, so `python ecav.py --build` (with no scenario arg) would fail before reaching the build step.
- Fix: hoisted the build check to the top of `main()`, before any scenario validation.

### `edge_process.py` — major additions
- `_FeatureStub` class (module-level): duck-types the interface `WorldFusionEdge.update_information()` and `run_step()` expect from a `VehicleManager`/`RSUManager`. Has nested `_PerceptionManager`, `_Localizer`, `_Vehicle`, `_Agent` classes. Populated entirely from `IntermediateFeatures` proto fields — no CARLA, no actual sensor objects.
- `EdgeProcess.expected_tick_id` and `_last_fusion_result`: tick-ID tracking for idempotent fusion RPCs. If `tick_id < expected_tick_id`, handler returns cached result; if out-of-order, returns empty.
- `EdgeServer.Edge_PerformFusion`: unpacks `IntermediateFeaturesBatch`, builds `_FeatureStub` instances (decompress + msgpack-unpack feature tensors), injects RSU/vehicle stubs into `edge_manager.rsu_manager_list` / `vehicle_manager_list` (RSUs first, maintaining WorldFusion agent-0=RSU invariant), calls `edge_manager.run_step(tick_id)`, packs per-vehicle pickled predictions into `FusionResult.pickled_predictions`.
- `EdgeServer.Edge_EndScenario`: calls `edge_manager.evaluate()`, serializes profiler dict into `EdgeEvaluationResult.pickled_edge_profiler`.
- `arg_parse()`: `--edge_index` default changed from required to `default=0`; added `--standalone` (skip orchestrator registration) and `--config <yaml_path>` flags.
- `_setup_edge_manager_standalone()`: instantiates edge_manager with `world=None, carla_client=None`. Member lists start empty; stubs injected per-tick by the `Edge_PerformFusion` handler.
- `_run_standalone()`: loads YAML from `--config`, runs phase A (`_init_edge_manager_model`) + standalone phase B (`_setup_edge_manager_standalone`), then calls `run_server()`. No orchestrator registration, no tick queue.
- `run()`: branches on `opt.standalone` at the top before the existing orchestrator-registration path.

### `edge_manager_worldfusion_ab3dmot_linear_predictor.py`
- `run_step()` had an unguarded `self.world.get_actors()` call in the Lincoln position logging block (separate from the `update_information()` call which is inside a try/except). Added `if self.world is not None:` guard.

## Key Decisions

**`_FeatureStub` as a duck-type rather than inheriting from VehicleManager/RSUManager**: The actual manager classes carry CARLA connections, sensors, and a lot of state we don't need. A minimal duck-type stub satisfying only the interface the edge manager touches is cleaner and has no CARLA dependency.

**RSU-first stub injection**: `Edge_PerformFusion` builds `rsu_stubs` and `vehicle_stubs` separately and injects RSUs first. This maintains the WorldFusion agent-0=RSU invariant (established in the 2026-04-26 fix). The batch sender (ecav.py, Phase 2) must also send RSUs first.

**Idempotent retry with `expected_tick_id`**: gRPC retries on transient failures are realistic under load. Returning the cached `_last_fusion_result` on a duplicate `tick_id` is cheaper than re-running fusion and avoids nondeterminism.
