## Key findings and fixes (chronological)

1. PACE build chain: cuda/12.1.1 module + `--no-build-isolation` +
   `TORCH_CUDA_ARCH_LIST=9.0` + CUPTI extras on LD_LIBRARY_PATH.
2. train_multiego routed MultiV2X to models_v2v4real (no lane encoder);
   fixed to models_opv2v. Aggregator hard-codes (50 frames, 48x176 BEV)
   parameterized. torch_geometric import guarded.
3. Loader rewritten to CMP's 22-attr agent features + 3D masks; yaw already
   radians (deg2rad bug); sparse-frame BatchNorm guard.
4. transformers==4.51.3 is the only line that works with torch 2.2.2 on
   PACE; Swin weights shipped offline inside mtr_code.tar.
5. eval_utils: dead psutil/pympler, opencood import chain made lazy,
   generate_prediction_dicts dispatched on dataset class, horizons derived
   from mask length, zero-future objects skipped (nan ADE).
6. **Big one:** export_wf_for_mtr.py used `build_dataset(train=True)` →
   translaug per-frame random world transforms → all exported trajectories
   scrambled (30-60 m/frame steps) while within-frame checks passed. Model
   trained to the static baseline (~31 m ADE). Fixed with train=False,
   verified cross-frame smoothness (max 3.1 m step), rebuilt intention
   points (also had a deg2rad bug; now forward-dominant dx [0,41]).
7. Retrain (job 10856291, 4x H200): stage 1 minADE 1.39 m / MR 0.221 —
   SUCCESS. Stage 2 aggregator diverged to nan — unusable, not needed.
