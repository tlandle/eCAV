### Bug: WorldFusion Agent Ordering

WorldFusion's fusion layer is ego-centric — it warps all agents' BEV features into **agent 0's spatial frame**. The post-processor is told `lidar_pose=[0,0,0,0,0,0]`, meaning it treats the coordinate origin as the reference frame. For this to be consistent, agent 0 must be the entity we define as origin — the RSU.

The code was collecting vehicles first, RSUs second → vehicle was agent 0, RSU was agent 1 → post-processor decoded boxes in the wrong frame every tick.

**Fix**: collect RSUs first (agent 0), vehicles after (agents 1..N). Also fixed `vehicle_poses = poses[num_rsus:]` in the self-beacon filter (was `poses[:num_vehicles]`, which was wrong when RSUs came last).

This is separate from Tyler's commit `c36e6084` (2026-04-20), which fixed the pairwise transform math and `lidar_pose`/`world_anchor` reference values. Tyler's fix was necessary but not sufficient — correct math on wrong-ordered agents still produces wrong output.

**Tyler confirmed (2026-04-26)**: both fixes are correct.
