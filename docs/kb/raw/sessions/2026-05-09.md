## Key Decisions

**Edge-only distributed architecture finalized:**

- Edge registers with ecav.py's asyncio gRPC server (not C++ ecloud_server). Receives edge_id + scenario config from registration response. No `--edge-index`, `--standalone`, or `--config` args needed at spawn.
- Edge is a pure fusion service — no tick push, no `Edge_TickComplete`, no C++ orchestrator in this mode.
- No CARLA connection in the edge container — actor positions travel in `IntermediateFeatures.pose`. ecav.py pre-computes `pairwise_t_matrix` from poses before calling `Edge_PerformFusion`. Edge does zero coordinate math.
- Batch mode (Phase 1): blocking `Edge_PerformFusion` RPC. Sequential tick loop has nothing else to do while fusion runs.
- Piecemeal mode (Phase 2): `Edge_SendIntermediateFeatures` per actor + blocking `Edge_GetFusionResult`. All three RPCs already defined in proto; handlers only missing.
- Tick-ID tracking on edge for idempotent gRPC retries.

**Edge never offloads to litserve (Tyler confirmed, architectural):**

- Edge is hardware-in-the-loop. Always runs fusion, tracking, and prediction locally (GPU).
- Vehicles can offload perception to litserve. Edge cannot and should not.

**SMART predictor is broken; MTR is the path:**

- SMART trained on Waymo, doesn't generalize to CARLA. HD map input never correctly wired. Predictions ~17m off.
- MTR (from CMP, pretrained) is being retrained by Tyler on WorldFusion inputs. Should work for our purposes.
