# Safety Envelope Paper — Data and Figures

This directory holds the evaluation artifacts for the paper
*Characterizing and Increasing the Safety Envelope for Edge-Assisted
Control of Autonomous Vehicles*.

## Directory layout

```
safety_envelope_paper/
├── README.md
├── experiment_results/         # Ground-truth simulation data
├── figures/                    # Published paper figures
├── figures_real/               # Aggregated plots from run data
└── figures_real_aligned/       # Per-ego aligned plots from run data
```

## `experiment_results/` — ground-truth simulation data

`experiment_results/` is the ground-truth dataset backing every figure
in the paper.  Each subdirectory is one run of the simulation test
runner and contains a `simulation_metrics.json` produced by the
evaluator at the end of the run.  The directory name encodes the
configuration:

```
mgr_<manager>__anchoring_<on|off>__lat_<ms>__ego_<N>__run_<R>__<scenario>/
    simulation_metrics.json
```

- `manager`: `oracle`, `late_fusion`, or `vips`
- `anchoring`: `on` (self-beacon anchoring enabled) or `off`
- `lat`: configured end-to-end delay in milliseconds (0, 50, 100, …, 550)
- `ego`: participant count $N \in \{1, 2, 4, 8, 16\}$
- `run`: repetition index (1--20 per configuration)
- `scenario`: NHTSA-derived scenario (`openscenario_ltap_od` or
  `openscenario_scp`)

Each `simulation_metrics.json` carries the per-vehicle brake
attributions, safety indicators, edge-side pipeline timings, AoI
samples, and detection / tracking / prediction quality produced by
the runtime.  The focal-ego metrics drive the safety-envelope
analysis; the edge block drives the timing, AoI, and uniqueness
analyses.

## How the data was produced

The data under `experiment_results/` was generated by the eCAV test
runner in closed-loop CARLA with the configurations enumerated in the
paper's methodology section.  Each run writes one
`simulation_metrics.json` through the standard evaluation pipeline at
the end of the scenario.  The 4,800 runs stored here cover:

- 3 managers × 2 anchoring modes (oracle is `on` only) × 12 latencies
  × 20 repetitions × 2 scenarios for the single-ego sweep;
- 3 managers × 2 anchoring modes × 3 representative latencies (100,
  200, 400 ms) × 4 participant counts (2, 4, 8, 16) × 20 repetitions
  × 2 scenarios for the multi-AV scaling sweep.

Cross-run variance sources include CARLA's GNSS noise model, LiDAR
dropout, YOLOv5 inference non-determinism, and AoI jitter under the
trace-driven component delay model.  The top-level
`simulation_metrics.json` files are self-contained and independent of
any runtime state; reproducing the figures only requires reading them
back through the aggregator.

## Aggregating and plotting

The aggregator and per-figure plot routines live in
`scripts/paper1_real_data_plots.py` and
`scripts/paper1_real_aligned_plots.py`.  The aligned entry point
reproduces the figures in the paper body:

```bash
python scripts/paper1_real_aligned_plots.py \
    safety_envelope_paper/experiment_results/<timestamp>
```

The `<timestamp>` subdirectory groups one campaign of runs.  Outputs
land in `safety_envelope_paper/figures_real_aligned/`.

| Figure file                        | Paper reference                                |
|------------------------------------|------------------------------------------------|
| `fig1_sop_vs_latency_ego1`         | Fig. 5 ($P(S_\mathrm{op})$ vs AoI)             |
| `fig2_failure_decomposition_ego1`  | Fig. 4 (component failure decomposition)       |
| `fig3_first_failure_stacked_ego1`  | First-failure stacked breakdown                |
| `fig4_oracle_isolation_ego1`       | Fig. 7 (failure-mode isolation)                |
| `fig5_aoi_cdf`                     | AoI CDF                                        |
| `fig6_multi_ego_scaling`           | Fig. 6 (multi-AV scaling at 100/200/400 ms)   |
| `fig8_brake_provenance_ego1`       | Fig. 9 (brake provenance breakdown)            |
| `fig9_brake_episodes_per_km_ego1`  | Brake episodes per km                          |

## Schema reference

Each `simulation_metrics.json` file has this shape:

```
{
  "target_speed_kmh": <int>,
  "config_manager_type": "<manager>",
  "config_anchoring": <bool>,
  "config_latency_ms": <float>,
  "config_ego_count": <int>,
  "config_scenario": "<scenario>",
  "collision_count": <int>,
  "success_rate": <float>,
  "vehicles": {
    "<actor_id>": {
      "actor_id": <int>,
      "avg_speed_mps": <float>,
      "total_brake_events": <int>,
      "ghost_brake_events": <int>,
      "distance_traveled_m": <float>,
      "safety": { "collision_count": <int>, "stuck": <bool>, ... },
      "brake_attributions": [
        {
          "tick": <int>,
          "trigger_tick": <int>,
          "source_tick": <int>,
          "track_id": <int>,
          "gt_brake_class": "self_ghost" | "other_fp" | "true_positive",
          "gt_provenance": "self" | "npc_hazard" | "parked" | "unknown",
          "gt_matched_actor_id": <int|null>
        }, ...
      ],
      ...
    }, ...
  },
  "edges": {
    "<edge_id>": {
      "timing_avg_ms": <float>, "timing_p95_ms": <float>,
      "timing_p99_ms": <float>,
      "detection_precision": <float>, "detection_recall": <float>,
      "tracking_avg_mota": <float>, "prediction_ade_1s_m": <float>,
      "aoi_mean_ms": <float>, "aoi_p99_ms": <float>,
      "ego_uniqueness": { ... },
      ...
    }
  },
  "simulation_timing": { ... },
  "safety_summary": { ... }
}
```

The aggregator reads each file, re-derives the focal-ego safety
indicators from the `brake_attributions` list via
`scripts/recompute_metrics.py:compute_run_metrics()`, and groups runs
by `(manager, anchoring, latency, ego_count)` for plotting.
